SSE（Server-Sent Events）是一种服务器向客户端单向推送数据的机制，本质上是基于 HTTP 的长连接。它不像 WebSocket 是双向的，而是利用 HTTP/1.1 的“chunked” 传输编码来保持连接打开。浏览器会自动处理重连（如果服务器建议），但默认情况下，SSE 连接容易被各种中间层（如代理、网关、运营商 NAT）中断，因为如果长时间没有数据，连接会被视为“空闲”而关闭。

核心在于解决SSE 的常见痛点：**超时、断连、心跳缺失、异常处理不当。**

#### **基础机制（SseEmitter 的异步和超时控制）**

- **原理**：Spring 的 SseEmitter 是为 SSE 设计的异步响应对象。它不会阻塞主线程（不像普通 @RestController），而是使用 Tomcat/Nett 等容器的异步 IO 支持。默认 HTTP 响应超时很短（e.g., 30 秒），但你设置了 new SseEmitter(TIMEOUT) 为 30 分钟，这告诉服务器“别急着关门”。同时，onTimeout/onCompletion/onError 回调确保连接异常时自动清理，避免资源泄漏。
- **为什么这样可以维持长连接**：避免了“响应太快结束”或“主线程卡住”。如果不这么做，连接可能在几秒内就断。
- **代码关联**：connect 方法创建 Emitter，并设置回调。

#### 2. **为什么有效：心跳机制（定期发送 keep-alive）**

- **原理**：许多代理（如 Nginx、Cloudflare）有“空闲超时”规则（e.g., 60 秒无数据就切断）。你的代码用 ScheduledExecutorService 每 30 秒发送一个“comment” 事件（:keep-alive），这是一种“空数据”包，不会触发客户端的 onmessage，但会让代理认为连接“活跃”。Comment 方式比空事件更好，因为它更隐蔽，不会干扰业务逻辑。
- **为什么这样可以维持长连接**：模拟了“持续数据流”，骗过了中间层的超时检测。在家用网络下，能维持几小时；在严格 CDN 下，至少能撑过 100 秒。
- **代码关联**：startHeartbeat 方法，使用 .comment("keep-alive")。

#### 3. **为什么有效：CORS 和跨域支持**

- **原理**：SSE 对跨域很敏感，如果前端域名不同，浏览器会阻塞连接。你的 SseConfig 用 WebMvcConfigurer 配置了 CORS（允许 * 起源、方法、头），并在控制器上加 @CrossOrigin("*")。这确保了前端能建立连接，而不会被 OPTIONS preflight 拒绝。
- **为什么这样可以维持长连接**：没有跨域，连接就能建起来；否则直接失败。
- **代码关联**：SseConfig 的 addCorsMappings。

#### 4. **为什么有效：重连建议和立即反馈**

- **原理**：SSE 内置重连机制（浏览器默认 3 秒重试一次），但你用 .reconnectTime(3000) 显式建议 3 秒重连。同时，连接时立即发送 "connected" 事件，让客户端知道成功。这减少了“盲等”时间。
- **为什么这样可以维持长连接**：断开后快速恢复，感觉像“一直连着”。
- **代码关联**：connect 方法的 emitter.send()。

#### 5. **为什么有效：异常和清理机制**

- **原理**：使用 ConcurrentHashMap 存储 emitter，确保线程安全。发送失败时 remove emitter，避免僵尸连接。广播/发送时 catch IOException，防止一个坏连接影响全局。
- **为什么这样可以维持长连接**：保持系统健康，防止内存/线程耗尽导致所有连接崩。
- **代码关联**：onError、try-catch 块。

#### 6. **潜在风险：为什么有时还是不行？**

- **外部因素**：网关层（如 Nginx 的 proxy_read_timeout 默认 60s）或运营商 NAT 可能忽略心跳，强制断开。解决方案：调大网关超时 + 缩短心跳到 15s。
- **内部因素**：如果心跳线程池崩溃，或 emitter.complete() 没调用，可能泄漏。极端高并发下，Map 可能成为瓶颈。
- **其他**：移动网络不稳、浏览器限制（e.g., Chrome 最多 6 个连接/域）。总体上，你的代码在“可控环境”下能维持 30min+，但不是 100% 永久。

总结：这个实现“可以”是因为它全面覆盖了 SSE 的保活要素（异步、心跳、超时、清理），远超简单 ResponseEntity<String> 的实现。但要完美，还需结合前端（EventSource withLastEventId）和网关配置。

package com.example.bookshare.sse;

import org.springframework.http.MediaType;
import org.springframework.web.bind.annotation.*;
import org.springframework.web.servlet.mvc.method.annotation.SseEmitter;
import java.io.IOException;
import java.util.Map;
import java.util.concurrent.ConcurrentHashMap;
import java.util.concurrent.Executors;
import java.util.concurrent.ScheduledExecutorService;
import java.util.concurrent.TimeUnit;

/**
 * SSE（Server-Sent Events）长连接控制器
 *
 * 保证长连接的关键点：
 * 1. 使用SseEmitter代替传统的@RestController  // 异步响应，避免阻塞。
 * 2. 定期发送心跳包（keep-alive）保持连接  // 防止代理超时。
 * 3. 客户端自动重连机制  // 通过 reconnectTime 建议。
 * 4. 异步处理，不阻塞主线程  // SseEmitter 内置异步。
 * 5. 异常处理和超时控制  // 回调确保清理。
 * 为什么整体有效：这些点覆盖了 SSE 的核心痛点，确保连接在网络允许下尽可能持久。
 */
@RestController  // 标记为 REST 控制器，返回 JSON 或其他媒体类型。
@RequestMapping("/api/sse")  // 所有端点前缀为 /api/sse。
@CrossOrigin(origins = "*")  // 类级 CORS 配置，补充 SseConfig；允许所有来源。
public class SseController {

    // 存储所有活跃的SSE连接
    // 使用 ConcurrentHashMap：线程安全，支持高并发读写。
    // 为什么有助于长连接：快速存取 emitter，避免锁争用导致延迟。
    private final Map<String, SseEmitter> emitters = new ConcurrentHashMap<>();
   
    // 心跳线程池
    // 使用 Executors.newScheduledThreadPool(5)：固定 5 个线程，够用且不浪费。
    // 为什么有助于长连接：独立线程发送心跳，不影响主业务。
    private final ScheduledExecutorService heartbeatExecutor = Executors.newScheduledThreadPool(5);
   
    // 默认超时时间（30分钟，设置为0表示永不超时）
    // 为什么有助于长连接：远超默认 30s，防止服务器主动超时；0 表示无限，但风险内存泄漏。
    // 优化建议：生产中别设 0，设 1-2 小时 + 强制重连。
    private static final long TIMEOUT = 30 * 60 * 1000L;
   
    // 心跳间隔时间（秒）
    // 为什么有助于长连接：30s 能覆盖大多数代理超时，但对 Cloudflare 等严格环境，建议改 15s。
    private static final int HEARTBEAT_INTERVAL = 30;

    /**
     * 建立SSE连接
     *
     * @param clientId 客户端唯一标识  // 用于区分不同客户端，如 userId 或 sessionId。
     * @return SseEmitter  // 返回异步响应对象。
     * 为什么有助于长连接：这里初始化一切保活机制。
     */
    @GetMapping(value = "/connect", produces = MediaType.TEXT_EVENT_STREAM_VALUE)  // produces 指定 text/event-stream，SSE 必须的 MIME 类型。
    public SseEmitter connect(@RequestParam String clientId) {
        // 创建SseEmitter，设置超时时间
        // 为什么有助于长连接：自定义超时，防止默认短超时断连。
        SseEmitter emitter = new SseEmitter(TIMEOUT);
       
        // 存储连接
        emitters.put(clientId, emitter);  // 添加到 Map，方便后续发送。
       
        // 设置完成和超时回调
        // 为什么有助于长连接：自动清理，防止泄漏导致系统崩溃。
        emitter.onCompletion(() -> {  // 连接正常完成时回调。
            System.out.println("连接完成: " + clientId);
            emitters.remove(clientId);
        });
       
        emitter.onTimeout(() -> {  // 超时回调。
            System.out.println("连接超时: " + clientId);
            emitters.remove(clientId);
            emitter.complete();  // 主动关闭，释放资源。
        });
       
        emitter.onError((ex) -> {  // 错误回调。
            System.err.println("连接错误: " + clientId + ", 错误: " + ex.getMessage());
            emitters.remove(clientId);
            // 优化建议：这里可以加 emitter.completeWithError(ex); 更彻底。
        });
       
        // 立即发送连接成功消息
        // 为什么有助于长连接：让客户端立即确认，减少初始延迟；同时设置 reconnectTime 指导重连。
        try {
            emitter.send(SseEmitter.event()  // 构建 SSE 事件。
                .id(String.valueOf(System.currentTimeMillis()))  // id：用于 last-event-id，重连时恢复。
                .name("connected")  // name：事件类型，客户端可监听。
                .data("SSE连接成功，客户端ID: " + clientId)  // data：实际消息。
                .reconnectTime(3000)); // 建议3秒后重连  // 优化建议：改成 1000ms，更快恢复。
        } catch (IOException e) {  // 发送失败处理。
            System.err.println("发送连接消息失败: " + e.getMessage());
            emitters.remove(clientId);
            return null;  // 返回 null，Spring 会处理为错误响应。
        }
       
        // 启动心跳检测，保持长连接
        // 为什么有助于长连接：核心保活机制，定期“戳”连接。
        startHeartbeat(clientId, emitter);
       
        System.out.println("新SSE连接建立: " + clientId + ", 当前连接数: " + emitters.size());
       
        return emitter;  // 返回 emitter，Spring 会异步处理。
    }

    /**
     * 向指定客户端发送消息
     *
     * @param request 发送消息请求  // 包含 clientId 和 message。
     * @return 发送结果  // JSON Map，success 和 message。
     * 为什么有助于长连接：发送时检查 emitter 存在，确保不发给已断连接。
     */
    @PostMapping("/send")
    public Map<String, Object> sendMessage(@RequestBody SendMessageRequest request) {
        SseEmitter emitter = emitters.get(request.getClientId());  // 获取 emitter。
       
        if (emitter == null) {  // 未连接处理。
            return Map.of(
                "success", false,
                "message", "客户端未连接或连接已断开"
            );
        }
       
        try {
            emitter.send(SseEmitter.event()  // 构建事件。
                .id(String.valueOf(System.currentTimeMillis()))
                .name("message")
                .data(request.getMessage())
                .comment("服务器推送消息"));  // comment：可选注释，不触发事件。
           
            return Map.of(
                "success", true,
                "message", "消息发送成功"
            );
        } catch (IOException e) {  // 发送失败。
            System.err.println("发送消息失败: " + e.getMessage());
            emitters.remove(request.getClientId());
            // 优化建议：加 emitter.completeWithError(e); 确保关闭。
            return Map.of(
                "success", false,
                "message", "发送失败: " + e.getMessage()
            );
        }
    }

    /**
     * 广播消息给所有连接的客户端
     *
     * @param message 消息内容  // Map 中 key 为 "message"。
     * @return 发送结果  // 包含 successCount 等统计。
     * 为什么有助于长连接：批量发送时逐个 try-catch，坏连接不影响好连接。
     */
    @PostMapping("/broadcast")
    public Map<String, Object> broadcast(@RequestBody Map<String, String> message) {
        String content = message.get("message");  // 提取消息。
        int successCount = 0;
        int failCount = 0;
       
        for (Map.Entry<String, SseEmitter> entry : emitters.entrySet()) {  // 遍历所有连接。
            try {
                entry.getValue().send(SseEmitter.event()
                    .id(String.valueOf(System.currentTimeMillis()))
                    .name("broadcast")
                    .data(content));
                successCount++;
            } catch (IOException e) {
                System.err.println("广播到客户端失败: " + entry.getKey());
                emitters.remove(entry.getKey());
                // 优化建议：加 entry.getValue().completeWithError(e);
                failCount++;
            }
        }
       
        return Map.of(
            "success", true,
            "totalClients", emitters.size(),
            "successCount", successCount,
            "failCount", failCount
        );
    }

    /**
     * 断开指定客户端连接
     *
     * @param clientId 客户端ID
     * @return 操作结果
     * 为什么有助于长连接：手动管理连接，防止无效连接占用资源。
     */
    @PostMapping("/disconnect")
    public Map<String, Object> disconnect(@RequestParam String clientId) {
        SseEmitter emitter = emitters.remove(clientId);  // 先移除。
        if (emitter != null) {
            try {
                emitter.send(SseEmitter.event()  // 发送断开消息。
                    .name("disconnect")
                    .data("服务器主动断开连接"));
                emitter.complete();  // 关闭连接。
                return Map.of("success", true, "message", "连接已断开");
            } catch (IOException e) {  // 发送失败也关闭。
                emitter.complete();
                return Map.of("success", true, "message", "连接已断开");
            }
        }
        return Map.of("success", false, "message", "客户端不存在");
    }

    /**
     * 获取当前连接数
     *
     * @return 连接信息  // totalConnections 和 connectedClients。
     * 为什么有助于长连接：监控用，便于调试连接问题。
     */
    @GetMapping("/stats")
    public Map<String, Object> getStats() {
        return Map.of(
            "totalConnections", emitters.size(),
            "connectedClients", emitters.keySet()  // 返回 Set<String>，客户端 ID 列表。
        );
    }

    /**
     * 启动心跳检测
     * 定期发送心跳包保持连接活跃
     *
     * @param clientId 客户端ID
     * @param emitter SseEmitter对象
     * 为什么有助于长连接：核心！防止空闲超时。
     */
    private void startHeartbeat(String clientId, SseEmitter emitter) {
        heartbeatExecutor.scheduleAtFixedRate(() -> {  // 固定间隔调度。
            if (!emitters.containsKey(clientId)) {  // 检查是否还活跃。
                return;  // 已移除则跳过。
            }
           
            try {
                // 发送心跳包（注释也是一种数据，不会触发客户端事件）
                // 为什么有效：comment 不会调用 onmessage，但保持 TCP 活跃。
                emitter.send(SseEmitter.event()
                    .comment("keep-alive"));
               
                System.out.println("心跳发送: " + clientId + " at " + System.currentTimeMillis());
            } catch (IOException e) {
                System.err.println("心跳发送失败: " + clientId + ", 错误: " + e.getMessage());
                emitters.remove(clientId);
                try {
                    emitter.complete();  // 失败时关闭。
                } catch (Exception ex) {
                    // 忽略二次异常。
                }
            }
        }, HEARTBEAT_INTERVAL, HEARTBEAT_INTERVAL, TimeUnit.SECONDS);  // 初始延迟=间隔，单位秒。
        // 优化建议：加随机偏移，避免所有心跳同时发导致峰值负载。
    }

    /**
     * 发送消息请求对象
     * 为什么：DTO 类，用于 @RequestBody 解析 JSON。
     */
    public static class SendMessageRequest {
        private String clientId;
        private String message;

        public String getClientId() {
            return clientId;
        }

        public void setClientId(String clientId) {
            this.clientId = clientId;
        }

        public String getMessage() {
            return message;
        }

        public void setMessage(String message) {
            this.message = message;
        }
    }
}

import org.springframework.http.MediaType;

 * SSE（Server-Sent Events）长连接控制器

 * 保证长连接的关键点：
 * 1. 使用SseEmitter代替传统的@RestController  // 异步响应，避免阻塞。
 * 2. 定期发送心跳包（keep-alive）保持连接  // 防止代理超时。
 * 3. 客户端自动重连机制  // 通过 reconnectTime 建议。
 * 4. 异步处理，不阻塞主线程  // SseEmitter 内置异步。
 * 5. 异常处理和超时控制  // 回调确保清理。
 * 为什么整体有效：这些点覆盖了 SSE 的核心痛点，确保连接在网络允许下尽可能持久。
 *
 * 改造说明：为支持大模型的流式输出，新增了 /stream 端点。
 * - 该端点接收用户查询 prompt，调用大模型 API（这里假设使用 OpenAI 或类似服务的 streaming API）。
 * - 在 SSE 连接中实时推送 token（流式输出）。
 * - 保持原有心跳机制，确保长连接稳定。
 * - 新增了 OpenAIService 示例（需注入实际服务），处理流式响应。
 * - 心跳间隔调整为 15 秒（更稳），并在流式发送失败时 complete。
 * - 假设你有 OpenAIClient 或类似客户端；需自行集成（如 spring-boot-starter-openai）。
 */
@RestController  // 标记为 REST 控制器，返回 JSON 或其他媒体类型。
@RequestMapping("/api/sse")  // 所有端点前缀为 /api/sse。
@CrossOrigin(origins = "*")  // 类级 CORS 配置，补充 SseConfig；允许所有来源。
public class SseController {

    // 存储所有活跃的SSE连接
    // 使用 ConcurrentHashMap：线程安全，支持高并发读写。
    // 为什么有助于长连接：快速存取 emitter，避免锁争用导致延迟。
    private final Map<String, SseEmitter> emitters = new ConcurrentHashMap<>();

    // 心跳线程池
    // 使用 Executors.newScheduledThreadPool(5)：固定 5 个线程，够用且不浪费。
    // 为什么有助于长连接：独立线程发送心跳，不影响主业务。
    private final ScheduledExecutorService heartbeatExecutor = Executors.newScheduledThreadPool(5);

    // 默认超时时间（30分钟，设置为0表示永不超时）
    // 为什么有助于长连接：远超默认 30s，防止服务器主动超时；0 表示无限，但风险内存泄漏。
    // 优化建议：生产中别设 0，设 1-2 小时 + 强制重连。
    private static final long TIMEOUT = 30 * 60 * 1000L;

    // 心跳间隔时间（秒）
    // 改造：从 30s 改为 15s，更适合大模型流式（生成首 token 可能 >30s）。
    private static final int HEARTBEAT_INTERVAL = 15;

    // 假设的大模型服务（需注入实际实现，如 OpenAI）
    @Autowired
    private OpenAIService openAIService;  // 示例服务，处理 LLM 流式调用。

    // JSON Mapper，用于序列化数据（可选，如果 data 是对象）。
    private final ObjectMapper objectMapper = new ObjectMapper();

    /**
     * 建立SSE连接（原有端点，保持不变）
     *
     * @param clientId 客户端唯一标识  // 用于区分不同客户端，如 userId 或 sessionId。
     * @return SseEmitter  // 返回异步响应对象。
     * 为什么有助于长连接：这里初始化一切保活机制。
     */
    @GetMapping(value = "/connect", produces = MediaType.TEXT_EVENT_STREAM_VALUE)  // produces 指定 text/event-stream，SSE 必须的 MIME 类型。
    public SseEmitter connect(@RequestParam String clientId) {
        // 创建SseEmitter，设置超时时间
        // 为什么有助于长连接：自定义超时，防止默认短超时断连。
        SseEmitter emitter = new SseEmitter(TIMEOUT);

        // 存储连接
        emitters.put(clientId, emitter);

        // 设置完成和超时回调
        // 为什么有助于长连接：自动清理，防止泄漏导致系统崩溃。
        emitter.onCompletion(() -> {  // 连接正常完成时回调。
            System.out.println("连接完成: " + clientId);
            emitters.remove(clientId);
        });

        emitter.onTimeout(() -> {  // 超时回调。
            System.out.println("连接超时: " + clientId);
            emitters.remove(clientId);
            emitter.complete();  // 主动关闭，释放资源。
        });

        emitter.onError((ex) -> {  // 错误回调。
            System.err.println("连接错误: " + clientId + ", 错误: " + ex.getMessage());
            emitters.remove(clientId);
            emitter.completeWithError(ex);  // 改造：使用 completeWithError 更彻底。
        });

        // 立即发送连接成功消息
        // 为什么有助于长连接：让客户端立即确认，减少初始延迟；同时设置 reconnectTime 指导重连。
        try {
            emitter.send(SseEmitter.event()  // 构建 SSE 事件。
                .id(String.valueOf(System.currentTimeMillis()))  // id：用于 last-event-id，重连时恢复。
                .name("connected")  // name：事件类型，客户端可监听。
                .data("SSE连接成功，客户端ID: " + clientId)  // data：实际消息。
                .reconnectTime(1000)); // 建议1秒后重连  // 改造：从 3000ms 改为 1000ms，更快恢复。
        } catch (IOException e) {  // 发送失败处理。
            System.err.println("发送连接消息失败: " + e.getMessage());
            emitters.remove(clientId);
            return null;  // 返回 null，Spring 会处理为错误响应。
        }

        // 启动心跳检测，保持长连接
        // 为什么有助于长连接：核心保活机制，定期“戳”连接。
        startHeartbeat(clientId, emitter);

        System.out.println("新SSE连接建立: " + clientId + ", 当前连接数: " + emitters.size());

        return emitter;  // 返回 emitter，Spring 会异步处理。
    }

    /**
     * 新增端点：大模型流式输出
     * 接收 prompt，启动 LLM streaming，并通过 SSE 实时推送 token。
     *
     * @param clientId 客户端ID（用于获取 emitter）
     * @param request 请求体，包含 prompt
     * @return 操作结果（成功启动或失败）
     * 改造说明：这是核心新增功能。异步调用 LLM，逐 token 发送。
     * - 使用 Executors.newSingleThreadExecutor() 异步处理 LLM 调用，不阻塞主线程。
     * - 每个 token 发送为 SSE 事件（name: "token"）。
     * - 生成完成后发送 "done" 事件。
     * - 如果 emitter 不存在，返回错误。
     */
    @PostMapping("/stream")
    public Map<String, Object> startStream(@RequestParam String clientId, @RequestBody StreamRequest request) {
        SseEmitter emitter = emitters.get(clientId);

        if (emitter == null) {
            return Map.of("success", false, "message", "客户端未连接");
        }

        // 异步启动 LLM 流式生成
        Executors.newSingleThreadExecutor().submit(() -> {
            try {
                // 调用大模型服务（假设返回一个 Flux<String> 或类似流）
                openAIService.streamCompletion(request.getPrompt())
                    .subscribe(
                        token -> {  // 每个 token
                            try {
                                emitter.send(SseEmitter.event()
                                    .name("token")
                                    .data(token));
                            } catch (IOException e) {
                                System.err.println("发送 token 失败: " + e.getMessage());
                                emitters.remove(clientId);
                                emitter.completeWithError(e);  // 改造：失败时 complete。
                            }
                        },
                        error -> {  // 错误
                            try {
                                emitter.send(SseEmitter.event()
                                    .name("error")
                                    .data("生成错误: " + error.getMessage()));
                                emitter.completeWithError(error);
                            } catch (IOException ignored) {}
                            emitters.remove(clientId);
                        },
                        () -> {  // 完成
                            try {
                                emitter.send(SseEmitter.event()
                                    .name("done")
                                    .data("生成完成"));
                                // 可选：不 complete，让连接继续用于下次 stream。
                            } catch (IOException ignored) {}
                        }
                    );
            } catch (Exception e) {
                System.err.println("LLM 调用失败: " + e.getMessage());
            }
        });

        return Map.of("success", true, "message", "流式生成已启动");
    }

    // 以下端点保持原有，略微优化异常处理
    /**
     * 向指定客户端发送消息
     *
     * @param request 发送消息请求  // 包含 clientId 和 message。
     * @return 发送结果  // JSON Map，success 和 message。
     * 为什么有助于长连接：发送时检查 emitter 存在，确保不发给已断连接。
     * 改造：失败时 completeWithError。
     */
    @PostMapping("/send")
    public Map<String, Object> sendMessage(@RequestBody SendMessageRequest request) {
        SseEmitter emitter = emitters.get(request.getClientId());

        if (emitter == null) {
            return Map.of(
                "success", false,
                "message", "客户端未连接或连接已断开"
            );
        }

        try {
            emitter.send(SseEmitter.event()  // 构建事件。
                .id(String.valueOf(System.currentTimeMillis()))
                .name("message")
                .data(request.getMessage())
                .comment("服务器推送消息"));  // comment：可选注释，不触发事件。

            return Map.of(
                "success", true,
                "message", "消息发送成功"
            );
        } catch (IOException e) {  // 发送失败。
            System.err.println("发送消息失败: " + e.getMessage());
            emitters.remove(request.getClientId());
            emitter.completeWithError(e);  // 改造：添加 complete。
            return Map.of(
                "success", false,
                "message", "发送失败: " + e.getMessage()
            );
        }
    }

    /**
     * 广播消息给所有连接的客户端
     *
     * @param message 消息内容  // Map 中 key 为 "message"。
     * @return 发送结果  // 包含 successCount 等统计。
     * 为什么有助于长连接：批量发送时逐个 try-catch，坏连接不影响好连接。
     * 改造：失败时 completeWithError。
     */
    @PostMapping("/broadcast")
    public Map<String, Object> broadcast(@RequestBody Map<String, String> message) {
        String content = message.get("message");  // 提取消息。
        int successCount = 0;
        int failCount = 0;

        for (Map.Entry<String, SseEmitter> entry : emitters.entrySet()) {  // 遍历所有连接。
            try {
                entry.getValue().send(SseEmitter.event()
                    .id(String.valueOf(System.currentTimeMillis()))
                    .name("broadcast")
                    .data(content));
                successCount++;
            } catch (IOException e) {
                System.err.println("广播到客户端失败: " + entry.getKey());
                emitters.remove(entry.getKey());
                entry.getValue().completeWithError(e);  // 改造：添加 complete。
                failCount++;
            }
        }

        return Map.of(
            "success", true,
            "totalClients", emitters.size(),
            "successCount", successCount,
            "failCount", failCount
        );
    }

    /**
     * 断开指定客户端连接
     *
     * @param clientId 客户端ID
     * @return 操作结果
     * 为什么有助于长连接：手动管理连接，防止无效连接占用资源。
     */
    @PostMapping("/disconnect")
    public Map<String, Object> disconnect(@RequestParam String clientId) {
        SseEmitter emitter = emitters.remove(clientId);  // 先移除。
        if (emitter != null) {
            try {
                emitter.send(SseEmitter.event()  // 发送断开消息。
                    .name("disconnect")
                    .data("服务器主动断开连接"));
                emitter.complete();  // 关闭连接。
                return Map.of("success", true, "message", "连接已断开");
            } catch (IOException e) {  // 发送失败也关闭。
                emitter.complete();
                return Map.of("success", true, "message", "连接已断开");
            }
        }
        return Map.of("success", false, "message", "客户端不存在");
    }

    /**
     * 获取当前连接数
     *
     * @return 连接信息  // totalConnections 和 connectedClients。
     * 为什么有助于长连接：监控用，便于调试连接问题。
     */
    @GetMapping("/stats")
    public Map<String, Object> getStats() {
        return Map.of(
            "totalConnections", emitters.size(),
            "connectedClients", emitters.keySet()  // 返回 Set<String>，客户端 ID 列表。
        );
    }

    /**
     * 启动心跳检测
     * 定期发送心跳包保持连接活跃
     *
     * @param clientId 客户端ID
     * @param emitter SseEmitter对象
     * 为什么有助于长连接：核心！防止空闲超时。
     * 改造：间隔改为 15s，并在失败时 completeWithError。
     */
    private void startHeartbeat(String clientId, SseEmitter emitter) {
        heartbeatExecutor.scheduleAtFixedRate(() -> {  // 固定间隔调度。
            if (!emitters.containsKey(clientId)) {  // 检查是否还活跃。
                return;  // 已移除则跳过。
            }

            try {
                // 发送心跳包（注释也是一种数据，不会触发客户端事件）
                // 为什么有效：comment 不会调用 onmessage，但保持 TCP 活跃。
                emitter.send(SseEmitter.event()
                    .comment("keep-alive"));

                System.out.println("心跳发送: " + clientId + " at " + System.currentTimeMillis());
            } catch (IOException e) {
                System.err.println("心跳发送失败: " + clientId + ", 错误: " + e.getMessage());
                emitters.remove(clientId);
                try {
                    emitter.completeWithError(e);  // 改造：使用 completeWithError。
                } catch (Exception ex) {
                    // 忽略二次异常。
                }
            }
        }, HEARTBEAT_INTERVAL, HEARTBEAT_INTERVAL, TimeUnit.SECONDS);  // 初始延迟=间隔，单位秒。
        // 优化建议：加随机偏移，避免所有心跳同时发导致峰值负载。
    }

    /**
     * 发送消息请求对象（原有）
     */
    public static class SendMessageRequest {
        private String clientId;
        private String message;

        public String getClientId() {
            return clientId;
        }

        public void setClientId(String clientId) {
            this.clientId = clientId;
        }

        public String getMessage() {
            return message;
        }

        public void setMessage(String message) {
            this.message = message;

    }

    /**
     * 流式请求对象（新增）
     */
    public static class StreamRequest {
        private String prompt;  // 用户查询 prompt

        public String getPrompt() {
            return prompt;
        }

        public void setPrompt(String prompt) {
            this.prompt = prompt;
        }
    }

    // 示例：大模型服务接口（需实现）
    // 假设使用 Reactor Flux 或类似流式返回每个 token。
    public interface OpenAIService {
        // 返回 Flux<String> 或 Observable<String>，每个元素是一个 token。

}

# CompletableFuture

![image-20260304100305731](C:\Users\11212\AppData\Roaming\Typora\typora-user-images\image-20260304100305731.png)

### 创建 CompletableFuture 的静态工厂方法

completedFuture(U value) 创建一个已经处于完成状态的 CompletableFuture，并直接持有指定的 value 值。这个方法常用于将同步结果快速包装成 CompletableFuture，或者在测试、mock、默认值场景中使用。它是立即返回的，不会涉及任何异步执行。

failedFuture(Throwable ex) 创建一个已经失败的 CompletableFuture，内部直接封装了传入的异常对象 ex。后续任何依赖它的链式调用（除非被 exceptionally 或 handle 捕获）都会抛出这个异常。主要用于提前构造错误结果或统一异常传播。

supplyAsync(Supplier<U> supplier) / supplyAsync(Supplier<U> supplier, Executor executor) 异步执行一个 Supplier 函数，并将其返回值作为 CompletableFuture 的结果。无 Executor 参数时使用 ForkJoinPool.commonPool() 作为默认线程池；有 Executor 参数时则使用指定的线程池执行。适用于大多数有返回值的异步计算任务。

runAsync(Runnable runnable) / runAsync(Runnable runnable, Executor executor) 异步执行一个不返回任何结果的 Runnable 任务，返回类型为 CompletableFuture<Void>。同样支持默认线程池或自定义 Executor，常用于执行副作用操作，例如打印日志、发送通知、更新 UI 等。

### 获取结果与状态查询

get() 和 get(long timeout, TimeUnit unit) 阻塞等待 CompletableFuture 完成并返回结果。如果任务以异常完成，则抛出 ExecutionException（包装了原始异常）；如果被中断则抛出 InterruptedException。带超时版本会在超时未完成时抛出 TimeoutException。这是最传统的阻塞获取方式。

join() 功能与 get() 类似，也是阻塞等待结果，但异常处理方式不同：它不会抛出 InterruptedException，而是直接抛出未经检查的 CompletionException（包装原始异常）。在现代代码中更常使用 join()，因为它更简洁且不需要处理 InterruptedException。

getNow(T valueIfAbsent) 非阻塞方法。如果当前 CompletableFuture 已经完成（正常或异常），返回其结果；否则立即返回传入的默认值 valueIfAbsent。常用于“有结果就用，没有就用默认值”的场景。

isDone()、isCompletedExceptionally()、isCancelled() 这三个方法用于查询状态。isDone() 返回是否已经完成（包括正常完成、异常完成、被取消）；isCompletedExceptionally() 判断是否以异常方式结束；isCancelled() 判断是否被 cancel() 方法取消过。

### 手动完成与超时控制

complete(T value) 尝试手动设置结果值并完成当前 CompletableFuture。如果该 Future 尚未完成，则设置 value 并返回 true；如果已经完成（无论正常还是异常），则本次调用无效，返回 false。常用于外部事件驱动完成或缓存场景。

completeExceptionally(Throwable ex) 尝试以异常方式手动完成 Future。如果尚未完成，则设置异常并返回 true；否则返回 false。常用于统一错误处理路径或模拟失败。

completeOnTimeout(T value, long timeout, TimeUnit unit) （Java 9+） 设置一个超时机制：如果在指定时间内 Future 仍未完成，则自动用 value 完成它，并返回自身（支持链式调用）。适合需要保底值的场景。

orTimeout(long timeout, TimeUnit unit) （Java 9+） 设置超时机制：如果超时仍未完成，则以 TimeoutException 异常完成 Future。同样返回自身，支持链式。

### 链式转换与消费（最核心的函数式方法）

thenApply(Function<? super T, ? extends U> fn) / thenApplyAsync(...) 当上游 CompletableFuture 正常完成时，将其结果传入 Function fn 进行转换，产生一个新的 CompletableFuture。thenApply 是同步调用（在上一个阶段的线程中执行 fn），thenApplyAsync 则是异步调度（默认线程池或指定 Executor）。这是最常用的结果映射方法。

thenAccept(Consumer<? super T> action) / thenAcceptAsync(...) 当上游完成时，消费其结果（执行 Consumer），但不产生新值，返回 CompletableFuture<Void>。常用于打印、保存结果、触发副作用等终端操作。

thenRun(Runnable action) / thenRunAsync(...) 当上游完成时（无论成功或失败），执行一个无入参、无返回值的 Runnable，返回 CompletableFuture<Void>。常用于“任务已结束”这样的日志或清理动作。

thenCompose(Function<? super T, ? extends CompletionStage<U>> fn) / thenComposeAsync(...) 当上游完成时，将结果传入 Function，该 Function 必须返回另一个 CompletionStage（通常是另一个 CompletableFuture），然后“展平”结果，返回新的 CompletableFuture。这是避免 Future 嵌套的关键方法，相当于 flatMap。

### 异常处理相关方法

exceptionally(Function<Throwable, ? extends T> fn) 仅当上游以异常完成时，才会执行该 Function，把 Throwable 作为输入，返回一个替代值 T（或抛出新异常）。如果上游正常完成，则直接透传原结果。常用于提供降级值或默认值。

handle(BiFunction<? super T, Throwable, ? extends U> fn) 无论上游是正常完成还是异常完成，都会执行该 BiFunction。参数依次为：结果（成功时有值，失败时为 null）和 Throwable（失败时有值，成功时为 null）。返回新的 CompletionStage。这是最灵活的“统一处理”方式。

whenComplete(BiConsumer<? super T, ? super Throwable> action) 当完成时（成功或失败）执行 BiConsumer，参数同 handle，但它不改变结果或异常，只是“观察”完成状态，返回原来的 CompletableFuture<T>。常用于记录日志、关闭资源、统计等副作用操作。

### 多任务组合方法

thenCombine(CompletionStage<? extends U> other, BiFunction<? super T, ? super U, ? extends V> fn) / thenCombineAsync(...) 等待当前 Future 和另一个 other 都完成，然后用 BiFunction 把两个结果组合成新值 V。常用于并行获取两个独立数据后再合并。

thenAcceptBoth(CompletionStage<? extends U> other, BiConsumer<? super T, ? super U> action) 等待两个都完成，然后消费两者的结果，但不产生返回值。

applyToEither(CompletionStage<? extends T> other, Function<? super T, U> fn) 当当前或 other 中任意一个先完成，就拿它的结果执行 Function，产生新结果。常用于“竞速”场景，取最快的结果。

allOf(CompletableFuture<?>... cfs) 静态方法，等待所有传入的 CompletableFuture 全部完成才完成，返回 CompletableFuture<Void>。常用于“所有任务都结束后再做某事”。

anyOf(CompletableFuture<?>... cfs) 静态方法，只要任意一个完成就完成，返回 CompletableFuture<Object>，结果是第一个完成的任务的结果。常用于“只要有一个成功就返回”。
